# #93 Tiled cache follow-ups

Follow-ups from the #44 review. Three independent tasks; shipped in two slices.

Reference check: not applicable (internal rendering performance; no product,
UX or format change).

## Slice 1 (this PR)

### Task 2: no allocation in `TiledElementPainter.paint()`
- `CachedTile` computes `src` (full-image source rect) once in its constructor.
- `TiledElementPainter._drawTile` draws `tile.image` from `tile.src` to
  `tile.rect` with the static paint, for visible and legacy tiles.

### Task 3: image load re-rasters only intersecting tiles
- `PageTileCache.invalidate(Iterable<Rect>)`: drops tiles of the current grid
  that intersect the rects (`TileStore.dropIn`, shared with the dirty path of
  `update`), releases legacy tiles, re-rasterizes visible ones.
- `ActiveLayerContentState` records the file paths of applied scene images that
  are not loaded yet (`_unloaded`, refreshed whenever a scene is applied). On an
  `ImageCacheManager` notification it invalidates only `imageBounds` of the
  images that loaded since. No cache rebuild, no `setState` (the painter
  repaints through the cache listenable).
- Test hook: `ImageCacheManager.debugPut` (`@visibleForTesting`).

Tests: `test/rendering/tiles/tile_invalidation_test.dart`.

## Slice 2: cache multiply-blend tiles

**Decision (architect, option A, see #93):** blend tiles are ordinary
transparent RGBA tiles rastered with the same element order and blend modes as
the vector painter. The ink layer is a transparent `RepaintBoundary` separate
from the page/PDF, so multiply over empty pixels is normal alpha, exactly as
the vector path renders it today; multiply against ink inside the tile stays a
real multiply. A true multiply over the page (option B: background and ink in
one surface) is #115, post-v1.0.

- `TileBuilder` (extracted from `PageTileCache`) builds every tile as one
  image: fresh, or the previous tile plus the appended elements.
- Multiply/screen tiles are rasterized; `vectorRects` stays empty for them.
  Overlay/darken/lighten (no v1.0 tool emits them) stay vectors.
- The earlier `A*B + K` image-pair design was dropped: it assumed an opaque
  destination in the same surface and would have blanked the page in the app.
- Parity tests (`blend_tile_test.dart`, `tiled_layer_golden_test.dart`) draw
  tiles and vectors into a transparent layer, then composite it over paper.
  Cases: highlighter over ink, highlighter over empty pixels, normal ink above
  a highlighter, cold build, undo.
- `tiled_layer_reference.png` is regenerated by the update-goldens workflow.
- The pen-up benchmark uses 30% multiply highlighters.
